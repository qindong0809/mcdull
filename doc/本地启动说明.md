# 本地启动说明

本文适用于 `revision 1.0.0`。业务服务统一使用 `local` / `test` / `prod` profile，`SPRING_PROFILES_ACTIVE` 必填（fail-fast）。环境配置统一在 `*-bootstrap`，`impl` 模块不再存放环境配置。

> 核心用法：复制第 1 节中对应服务的整行环境变量，粘贴到 IDE 的 `Environment variables`，然后启动对应启动类即可。
>
> 示例中的 `NACOS_PWD=123456` 按你提供的基线保留；若本机 Nacos 仍是默认的 `nacos/nacos`，把该值改回 `nacos`。
>
> 首次启动前请先在仓库根目录执行 `mvn clean install`（需要本机已安装 Maven 3.9.x，并配好全局 `settings.xml` 的内网 nexus 镜像）。该命令默认会跑单元测试与各模块的 ArchUnit 架构检查，请勿加 `-DskipTests`（仅本地紧急排查可临时使用，提交前须复验）。

---

## 1. 一键复制环境变量（重点）

三套 profile（`local` / `test` / `prod`）的**键集合完全一致**，只需替换 `SPRING_PROFILES_ACTIVE` 和对应环境的值。每个服务 10 项：公共 4 项 + 服务前缀 6 项。

已省略三套均有相同默认值的变量，无需再写：`*_REDIS_PORT`（6379）、`*_REDIS_DB`（1）、`*_REDIS_PASSWORD`（空）、`*_REDIS_TIMEOUT`（system 10s / 其他 3s）、`*_DRUID_ADMIN_USER`（root）、`*_DRUID_ADMIN_PASSWORD`（空）。

`*_DB_HOST` 只写主机名，端口 3306、库名和连接参数已在各服务 yml 中写死，不再提供完整 JDBC URL。

### 1.1 公共基线

所有业务服务都以此开头（4 项）：

```text
SPRING_PROFILES_ACTIVE=local;NACOS_ADDR=mcdull.io:8848;NACOS_USER=nacos;NACOS_PWD=123456
```

### 1.7 mcdull-gateway（9090）

网关已与业务服务统一使用 `local` / `test` / `prod` 和 fail-fast。网关无数据库，只有 6 项（公共 4 项 + 网关前缀 2 项）：

```text
SPRING_PROFILES_ACTIVE=local;NACOS_ADDR=mcdull.io:8848;NACOS_USER=nacos;NACOS_PWD=123456;GATEWAY_SERVER_PORT=9090;GATEWAY_REDIS_HOST=mcdull.io;GATEWAY_LOG_PATH=./logs
```

### 1.8 mcdull-monitor-server（9000，回环监听）

监控平台为独立信任域，已启用 Spring Security，**密码必填且不少于 12 位**，缺失或过短直接启动失败（fail-closed）。默认只监听 `127.0.0.1`，远程访问请通过 SSH 隧道或内网 Ingress，不要直接暴露 9000 端口。

```text
MONITOR_SECURITY_PASSWORD=change-me-12chars-plus
```

可选变量：`MONITOR_SECURITY_USER`（默认 `admin`）、`MONITOR_BIND_ADDRESS`（默认 `127.0.0.1`）。

浏览器访问 `http://localhost:9000`，使用上述账号登录；SBA 已放行表单登录、静态资源与 `/actuator/health`，其余端点均需认证。

## 2. 首次启动前置：口令列扩列

业务用户口令已从无盐 SHA1 平滑迁移到 BCrypt（60 字符），而存量 `sys_user.login_pwd` 为 `varchar(50)`。**必须先执行扩列脚本**，否则老用户登录时透明升级会写入失败（不阻断登录，但会持续告警且永远升不上去）：

```sql
-- 仓库脚本：release/sql/4.1_password_bcrypt_upgrade.sql
ALTER TABLE `sys_user` MODIFY COLUMN `login_pwd` varchar(255) NOT NULL COMMENT '登录密码';
```

`administrator_user` / `app_user` 原为 `varchar(64)`，已可容纳 BCrypt，无需扩列。

前端协议未改动：仍传 `Base64(AES(明文))`。AES 密钥由 `MCDULL_PASSWORD_AES_KEY` 注入，默认值与前端硬编码值一致；使用默认值时启动会打 WARN。老用户登录成功后会自动升级为 BCrypt，失败只告警不阻断登录。迁移观察期结束后，设置 `MCDULL_PASSWORD_LEGACY_ENABLED=false` 可拒绝未升级的存量口令。
