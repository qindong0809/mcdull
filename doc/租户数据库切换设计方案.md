# 租户数据库切换设计方案

> 业务场景：用户选中指定租户后，后续请求自动路由到该租户对应的数据库。
>
> 模型：**仅按 tenantId 切库**。用户只决定「能访问哪些租户」，不影响路由 key。

---

## 请求时序

```text
前端：用户选中租户 42
  └─ 请求头携带 tid: 42

① HttpTraceLogFilter (order=2)
  ├─ 建立 UnifySession、注入 traceId
  └─ 不触碰数据源（Filter 层无访问 DB 的组件）

② AuthSessionFilter (order=3)
  └─ sa-token → UnifySession.userId / tenantId

③ DynamicDatasourceInterceptor（MVC 层，唯一切库点）
  ├─ 本地能获取 master 配置（system 服务，含登录接口）→ 用 master，不切租户库
  ├─ 取 tenantId = 请求头 tid
  │    为空 → throw BusinessException("system.tenant.required")
  ├─ 校验 tenantId ∈ 登录时存入 Redis 的用户授权租户集合
  │    不包含 → throw BusinessException("system.tenant.forbidden")
  ├─ 解析数据源（其它微服务）：
  │    缓存命中 → 直接返回
  │    未命中 → system-feign 查询 master 库 → 写入缓存 → 返回
  ├─ 注册物理连接池（若未注册）
  └─ push(tenantKey) → request 记录该 key

④ Controller → @Transactional → Service → Mapper
  └─ 路由到 tenantId=42 对应的数据库

⑤ afterCompletion
  └─ 按 request 记录的 key 精确 remove，不动其他上下文

⑥ HttpTraceLogFilter finally
  └─ 清空会话与路由上下文
```

**关键约束**：

- 请求头 uid 不可信，身份只取服务端会话。
- tid 仅表示"用户当前选择"，必须属于用户授权租户集合才能切库。
- 事务在开启时绑定连接，单请求单库，不跨库写。
