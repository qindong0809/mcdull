## 1. 执行摘要

`5.1_tenant.sql` 已经交付 master 库侧的数据模型（`sys_tenant`、`sys_datasource`、`sys_tenant_user`、`sys_tenant_menu`，并为 `sys_menu` 增加 `application_code`），框架层也已具备"仅按 tenantId 切库"的拦截器与 SPI 契约。但当前 `system-impl` 中没有租户相关实体、服务与 Controller，前端仓库没有租户页面、API 与路由，登录流程未写入 `tenantIds`，内部 RPC 接口无服务端实现。

本期目标：在不改变既有切库模型的前提下，补齐"数据源配置 → 租户建档 → 用户/菜单授权 → 租户库初始化 → 登录选租户 → 请求按 tid 切库"的完整业务闭环，并在管理后台提供可操作、可审计、符合 SmartForm 视觉基准的界面。

| 能力 | 当前状态 | 本期目标 |
|---|---|---|
| 数据模型 | 5.1 脚本已定义 4 张表 + `sys_menu` 增量字段 | 保留表结构；补充关系表删除策略（物理删除规避唯一键冲突）与条件唯一索引建议 |
| 切库框架 | `DynamicDatasourceInterceptor` + SPI 已实现，默认关闭 | 开启路由开关；补齐异常码与配置 |
| 内部 RPC | `TenantDataSourceApiDef` 定义 2 个接口 | `system-impl` 实现并接入缓存与解密 |
| 后台管理 | 前端/后端均无租户、数据源模块 | 新增列表、表单、授权、初始化页面与 API |
| 登录授权 | `UnifySession` 有 `tenantIds` 字段但未写入 | 登录时由 `sys_tenant_user` 生成授权租户集合 |
| 菜单应用归属 | `sys_menu.application_code` 仅存在于 SQL | 菜单实体/前端筛选/全局菜单树支持应用过滤 |

## 2. 范围、角色与边界

### 2.1 本期范围

- master 库侧：数据源配置、租户建档、租户-用户关系、租户-菜单白名单、菜单应用归属的 CRUD 与查询。
- 租户库侧：初始化脚本执行、`database_name` 回写、`init_status` 状态流转与失败重试入口。
- 运行时：登录生成 `tenantIds`、前端租户切换器传递 `tid`、内部接口返回数据源、缓存与解密。
- 管理后台：新增租户管理、数据源管理页面，改造菜单管理以支持 `application_code`。

### 2.2 不在本期范围

- `isolation_mode=2`（共享库-行隔离）：SQL 中已标注为预留，接口层必须拒绝配置，待框架配套后开放。
- 跨库事务、租户库结构差异管理、计费/订单、租户自助注册。
- 大规模自动化运维（批量初始化任务调度、脚本版本升级）仅预留扩展点。

### 2.3 角色与权限边界

| 角色 | 职责 | 可见范围 |
|---|---|---|
| 平台超级管理员 | 配置数据源、创建/删除租户、执行初始化、配置用户与菜单白名单 | 全部租户与数据源 |
| 平台运营/支持 | 查看租户、配置用户与菜单白名单、发起初始化 | 被授权的租户 |
| 租户管理员 | 在租户库内配置角色与菜单授权；切换本租户 | 仅自己所属租户 |
| 普通用户 | 登录后在授权租户间切换 | `sys_tenant_user` 中授权且状态正常的租户 |

## 3. 现状分析（后端 / 前端 / 数据）

### 3.1 数据模型关系

```text
sys_datasource (1) ────< (N) sys_tenant          数据源可被多个租户共用
sys_tenant     (1) ────< (N) sys_tenant_user     一个用户可属于多个租户
sys_tenant     (1) ────< (N) sys_tenant_menu     租户级菜单白名单
sys_menu.application_code  ← 租户 application_code JSON 集合（应用过滤）

路由映射：key=sys_tenant.database_name(tenant_{id}), tenantId=sys_tenant.id,
          url/username=sys_datasource, password=decrypt(password_cipher)
```

### 3.4 差距清单

| 编号 | 差距 | 影响 | 优先级 |

## 4. 数据字典与字段规则

### 4.1 sys_tenant（租户主表）

| 字段 | 类型/约束 | 业务含义 | 前端控件与规则 |
|---|---|---|---|
| `id` | int PK 自增 | 租户 ID，同时用于生成 `database_name` | 列表展示（等宽数字）；新建时不可填 |
| `tenant_name` | varchar(128) NOT NULL；活跃唯一 | 租户名称 | 输入，必填，1-128 字符；重名校验仅针对 `del_flag=0` |
| `datasource_id` | int NOT NULL | 关联 `sys_datasource.id`，多对一 | 下拉，必填，仅展示未失活且未删除的数据源 |
| `database_name` | varchar(64) NULL | 路由 lookupKey，规则 `tenant_{id}` | 只读展示；初始化成功后自动赋值，任何角色不可修改 |
| `owner_type` | tinyint NOT NULL default 1 | 1企业 2团队 3个人 4试用 5内部 | `SmartEnumSelect`，必填；选择"试用"时到期时间必填 |
| `isolation_mode` | tinyint NOT NULL default 1 | 1独立库 2共享库行隔离（预留） | `SmartEnumSelect`，必填；仅允许 1，选择 2 时接口拒绝并提示 |
| `expire_time` | datetime NULL | 到期时间；NULL=长期有效 | DatePicker；试用类型必填且必须晚于当前时间 |
| `init_status` | tinyint NOT NULL default 0 | 0未初始化 1初始化中 2成功 3失败 | Tag/文字只读；驱动"初始化/重试"按钮可见性 |
| `application_code` | varchar(512) NULL | 关联应用 code JSON 集合 | 多选；提交为 JSON 数组字符串；决定初始化脚本目录与菜单过滤 |
| `tenant_name_key` | 生成列 + 条件唯一索引 | 删除后置 NULL，允许重建同名租户 | 不展示；由数据库维护 |
| 审计与状态 | `created_by/time`、`updated_by/time`、`inactive`、`del_flag`、`remark` | 标准审计字段 | 状态用启用/停用切换；删除为逻辑删除；remark 文本域 |

### 4.2 sys_datasource（数据源配置表）

| 字段 | 类型/约束 | 业务含义 | 前端控件与规则 |
|---|---|---|---|
| `id` | int PK 自增 | 数据源 ID | 列表展示，供租户下拉引用 |
| `datasource_name` | varchar(128) NOT NULL | 下拉显示名称 | 输入必填；建议增加活跃唯一校验（见 G09） |
| `jdbc_url` | varchar(512) NOT NULL | JDBC 连接串 | 输入必填；格式校验；列表中脱敏展示 |
| `username` | varchar(64) NOT NULL | 数据库账号 | 输入必填 |
| `password_cipher` | varchar(512) NOT NULL | AES+Base64 密文 | 密码框只写不回显；留空表示不修改；测试连接时优先用本次输入明文，留空则用已存密文临时解密；明文禁止进入日志/VO/缓存 |
| 审计与状态 | 标准审计字段 + `inactive` + `del_flag` + `remark` | 状态与生命周期 | 被租户引用时禁止删除，停用需二次确认 |

### 4.3 sys_tenant_user / sys_tenant_menu

| 表.字段 | 约束 | 业务含义 | 交互规则 |
|---|---|---|---|
| `sys_tenant_user.tenant_id` / `user_id` | unique(tenant_id,user_id) | 一个用户可属于多个租户 | 弹窗多选添加；移除采用物理删除，避免软删后唯一键冲突 |
| `sys_tenant_menu.tenant_id` / `menu_id` | unique(tenant_id,menu_id) | 租户级菜单白名单 | 树形勾选；保存时全量替换；角色级授权仍在租户库内完成 |
| 审计与状态 | 标准审计字段 + `inactive` + `del_flag` | 关系生命周期 | 本期关系移除统一物理删除；审计需求后续用条件唯一索引支持 |

### 4.4 sys_menu.application_code 增量

通过 `information_schema` 判断实现可重放，新增 `application_code varchar(64) NOT NULL DEFAULT 'system'`。该字段用于：

1. 租户菜单白名单树按应用过滤；
2. 菜单管理页面展示"归属应用"；
3. 登录返回菜单时按租户 `application_code` 进行交集过滤。

**两个 `application_code` 语义必须区分：**

| 字段 | 所在表 | 语义 | 示例 |
|---|---|---|---|
| `sys_tenant.application_code` | 租户主表 | 该租户开通了哪些业务应用 | `["OA","HR"]` |
| `sys_menu.application_code` | 全局菜单树 | 该菜单/按钮归属哪个应用 | `system`、`OA`、`HR` |

本期新增的租户管理、数据源配置页面及其按钮均归属于 **`system` 应用 / 平台系统管理域**：

- 菜单记录写入 master 库 `sys_menu`，`application_code` 显式写 `system`，不能写成租户开通的 OA/HR/CRM。
- 租户管理按钮权限串使用 `system:tenant:query/write/delete/init`；数据源按钮使用 `system:datasource:query/write/delete/test`。
- `sys_tenant_menu` 只是“哪些租户可用这些菜单”的白名单引用，不改变菜单本身的应用归属。
- 菜单归属判断原则是“谁管理它”，不是“它管理谁”。

## 5. 核心业务规则与状态机

| 编号 | 规则 | 说明 |
|---|---|---|
| BR-01 | 活跃租户名唯一 | 依赖生成列 `tenant_name_key` + `uk_tenant_name_active`；逻辑删除后名称可重建 |
| BR-02 | `database_name` 自动生成且不可修改 | 初始化成功时赋值 `tenant_{id}`，作为唯一路由 key |
| BR-03 | 仅支持独立库 | `isolation_mode=2` 时接口直接拒绝，提示"共享库行隔离暂未开放" |
| BR-04 | 数据源引用保护 | 被任一未删除租户引用的数据源不可删除；停用需二次确认并提示影响范围 |
| BR-05 | 密码安全 | 独立密钥 `mcdull.security.datasource.aes-key`（环境变量注入）；明文不入库、不进日志、不进缓存；缓存 VO 存密文，用时解密 |
| BR-06 | 应用集合 | `application_code` 为 JSON 数组字符串；`sys_menu.application_code` 默认 system；菜单白名单只展示租户已选应用或全部应用（由筛选器选择） |
| BR-07 | 初始化状态机 | 见下表；仅 `init_status=2` 的租户进入登录授权集合 |
| BR-08 | 关系表移除策略 | 租户-用户、租户-菜单关系移除采用物理删除，规避唯一键包含已删除行的问题 |
| BR-09 | 到期策略 | `expire_time` 为空表示长期有效；已过期租户不进入可切换列表，请求返回 `system.tenant.expired`（待确认文案） |
| BR-10 | 最终菜单权限 | 最终可见菜单 = 角色授权菜单 ∩ 租户菜单白名单 ∩ 应用归属过滤；交集在登录/切换租户返回 `menuList` 时由 system 服务计算，前端只负责渲染 |
| BR-11 | 数据源测试连接 | 保存前可验证连通性：使用表单当前输入（编辑时密码留空则用已存密文临时解密），单次请求、5s 超时、不注册物理连接池、不写库、不进缓存；仅返回成功/失败、耗时与数据库版本，错误文案需脱敏 |
| BR-12 | 菜单与按钮归属 | 租户管理、数据源配置及其按钮统一归属 `system` 应用，菜单记录写入 master 库 `sys_menu` 且 `application_code='system'`；权限串以 `system:tenant:*` / `system:datasource:*` 命名；不得按租户开通的 OA/HR/CRM 设置归属 |
| BR-13 | 门户租户上下文 | 门户是登录首屏，租户是首要上下文；门户顶部提供轻量租户切换器。租户级应用卡片、KPI、待决策与事件流按当前 `tid` 重新拉取；平台级系统卡片按平台权限显示，不按租户开通应用过滤；切换租户后必须刷新菜单动态路由并隔离 Agent/AI 会话上下文 |
| BR-14 | 登录租户集合与当前租户 | 登录时查 `sys_tenant_user` join `sys_tenant`，过滤停用/删除/未初始化/过期租户，得到 `tenantIds` 并写入 `UnifySession`（Redis 会话）；完整 `tenantList` 由登录信息接口返回前端。当前选中的租户只由前端维护，每个请求以 `tid` 传递，服务端按 `tid ∈ session.tenantIds` 逐请求校验。单租户自动选中；多租户默认第一个可用租户但必须显式展示并可切换；无租户展示空状态。当前租户不写入 Redis 会话，避免多标签页互相影响 |
| BR-15 | 初始化进度实时推送 | 初始化改为异步任务：点击后先返回 `taskId`，再通过 SSE 推送步骤级进度（步骤名、百分比、日志、错误摘要、最终状态）。同一租户同时只允许一个运行中任务；订阅断线后按 `taskId` + `Last-Event-ID` 续接并先补发当前快照；心跳保持连接；前端关闭弹窗不取消任务，仅断开订阅。system 服务使用 master 数据源，SSE 端点通过查询参数传 `tid`，服务端仍按会话 `tenantIds` 校验 |
| BR-16 | 初始化预检与建库顺序 | 初始化必须先预检目标库名 `tenant_{id}` 是否存在，再决定是否执行 `CREATE DATABASE`，最后按 `application_code` 顺序执行各应用脚本。库不存在则建库并在任务快照记录 `databaseCreated=true`；库已存在且非本任务创建时立即失败（`init_status=3`），不建库、不执行脚本、不回写 `database_name`；同租户重试且快照显示 `databaseCreated=true` 时跳过建库并从失败脚本继续；`force=true` 重新初始化时库已存在且归属当前租户，跳过建库并幂等重放脚本。严禁覆盖、清空或删除未知同名库 |

### init_status 状态机

| 当前状态 | 触发动作 | 下一状态 | 副作用 |
|---|---|---|---|
| 0 未初始化 | 点击"执行初始化" | 1 初始化中 | 校验数据源连通性 → 预检 `tenant_{id}` 是否存在 → 不存在则 `CREATE DATABASE` → 按 `application_code` 执行脚本；**不提前写入 `database_name`** |
| 1 初始化中 | 预检发现未知同名库 | 3 失败 | 立即终止，不建库、不执行脚本、不回写 `database_name`；提示数据库已存在并需管理员处理 |
| 1 初始化中 | 建库失败 | 3 失败 | 记录失败步骤；不执行应用脚本；不写入 `database_name` |
| 1 初始化中 | 全部脚本执行成功 | 2 成功 | 写入 `database_name=tenant_{id}`、记录日志；租户进入可授权/可切换列表 |
| 1 初始化中 | 任一应用脚本失败 | 3 失败 | 保留已建库状态 `databaseCreated=true` 与失败脚本位置；允许重试；不写入 `database_name` |
| 3 失败 | 点击"重试" | 1 初始化中 | 若快照 `databaseCreated=true` 则跳过预检结论复用与建库，从失败脚本继续；否则重新预检并建库；脚本需幂等 |
| 2 成功 | 点击"重新初始化"（`force=true`） | 1 初始化中 | 高风险操作，需二次确认；仅平台超管可见；库已存在且归属当前租户时跳过建库、幂等重放脚本；执行期间保留原 `database_name`，失败不清除 |

### 7.1 管理端接口（system-impl 新增）

| 接口 | 方法 | 说明 | 关键入参/出参 |
|---|---|---|---|
| `/system/tenant/page` | POST | 租户分页查询 | `tenantName`、`ownerType`、`initStatus`、`inactive`、`applicationCode`、`pageNum/pageSize` |
| `/system/tenant` | POST | 新增租户 | `tenantName`、`datasourceId`、`ownerType`、`isolationMode`、`expireTime`、`applicationCode`、`remark` |
| `/system/tenant` | PUT | 编辑租户 | `id` + 上述可编辑字段；`databaseName`/`isolationMode`（初始化后）不可改 |
| `/system/tenant/{id}` | GET / DELETE | 详情 / 逻辑删除 | 详情含 `userCount`、`menuCount`、`initStatus` |
| `/system/tenant/{id}/status` | POST | 启停切换 | `inactive` |
| `/system/tenant/{id}/init` | POST | 启动初始化/重试任务；`force=true` 表示已初始化租户的"重新初始化" | 入参 `force?`；立即返回 `taskId`、`initStatus=1`、`currentStep=DB_EXISTS_CHECK`；不等待预检、建库与脚本执行完成 |
| `/system/tenant/init-progress/{taskId}` | GET（SSE） | 订阅初始化实时进度，`produces=text/event-stream` | 查询参数 `tid`；事件：`snapshot`/`step`/`log`/`progress`/`success`/`fail`/`heartbeat`/`done`；数据含 `taskId`、`stepCode`、`stepName`、`progress`、`message`、`databaseName`、`databaseCreated`、`applicationCode`、`scriptIndex`、`errorCode`、`timestamp` |
| `/system/tenant/{id}/users` | GET / POST / DELETE | 用户列表 / 批量添加 / 批量移除 | `userIds[]` |
| `/system/tenant/{id}/menus` | GET / POST | 菜单树（含选中态）/ 保存白名单 | `applicationCode`、`keyword`；保存 `menuIds[]` |
| `/system/datasource/page` | POST | 数据源分页 | `datasourceName`、`inactive`、`pageNum/pageSize` |
| `/system/datasource` | POST / PUT | 新增 / 编辑 | `datasourceName`、`jdbcUrl`、`username`、`password`（明文入参，服务端加密） |
| `/system/datasource/{id}` | GET / DELETE | 详情（密码掩码） / 逻辑删除 | 检查引用计数 |
| `/system/datasource/{id}/status` | POST | 启停切换 | `inactive` |
| `/system/datasource/options` | GET | 租户表单数据源下拉 | 仅返回未删除且启用的 `id/name` |
| `/system/datasource/test-connection` | POST | 测试数据源连通性 | 入参 `id?`、`jdbcUrl`、`username`、`password`；出参 `success`、`message`、`latencyMs`、`databaseProduct`、`databaseVersion` |
| `GET /current/user-info` | GET | 既有登录信息接口（前端封装为 `getLoginInfo()`） | 新增返回 `tenantList`：`id`/`name`/`applicationCode`/`initStatus`/`expireTime`；不返回密码、数据源连接信息等敏感字段 |
| `/system/portal/overview` | GET | 门户首屏聚合数据 | 入参 `tid`（请求头）；出参 `tenant`、`apps[]`（含 `scope`/`applicationCode`）、`kpi`、`decisions[]`、`events[]`；切换租户时重新调用 |
| `/system/menu/options` | GET | 菜单下拉/白名单树 | 增加 `applicationCode` 入参 |

**初始化进度约定**：原生 `EventSource` 不能设置自定义请求头，因此 SSE 订阅通过查询参数传 `tid`，服务端必须用会话 `tenantIds` 校验，且不得信任其他身份参数。任务状态写入 Redis（TTL 24h）并新增 `sys_tenant_init_task` 记录表保存任务快照与日志，字段至少含 `databaseName`、`databaseCreated`、`currentStepCode`、`scriptIndex`、`scriptStatuses`、`errorCode`，用于刷新页面/断线续接/重试判定与历史查看。步骤码固定为 `DB_EXISTS_CHECK`、`CREATE_DATABASE`、`APP_SCRIPT`、`WRITE_BACK`、`DONE`；每次订阅先发送 `snapshot`，后续按步骤推送进度，每 15s 发送 `heartbeat` 防止代理缓冲断连。`fail` 事件必须携带 `failedStepCode`，前端据此展示“库名已存在 / 建库失败 / 某应用脚本失败”。

**测试连接约定**：新建场景 `password` 必填（与 `password_cipher NOT NULL` 对齐）；编辑场景传空字符串表示保留原密文，服务端用 `mcdull.security.datasource.aes-key` 临时解密已存 `password_cipher` 用于本次测试。`password` 为本次请求体内临时明文，仅用于建立一次 JDBC 连接，用后立即丢弃，不落库、不写日志、不缓存。响应只返回结论、耗时与数据库元信息，错误文案需剔除 URL 参数与账号密码。

### 7.2 内部接口（沿用既有契约）

| 接口 | 契约位置 | 实现要求 |
|---|---|---|
| `POST /inner/system/tenant-datasource/by-tenant?tenantId=` | `TenantDataSourceApiDef` | 查 `sys_tenant` + `sys_datasource`，校验状态，解密密码，返回 `RemoteTenantDataSourceInfoVO` |
| `POST /inner/system/tenant-datasource/authorized-tenants?userId=` | `TenantDataSourceApiDef` | 查 `sys_tenant_user` join `sys_tenant`，过滤 `del_flag`/`inactive`/`init_status`/`expire_time`，返回 `Set<Integer>` |

**运行时约定**：登录时查询授权租户集合并写入 `UnifySession.tenantIds`（落在 Redis 会话中），它用于鉴权，是“用户能访问哪些租户”的唯一权威来源；为空时拦截器回源 `authorized-tenants` 并回填会话。`currentTenantId` 不写入 Redis，只由前端维护：单租户自动选中，多租户默认第一个可用租户，后续请求以 `tid` 传递。服务端逐请求校验 `tid ∈ tenantIds`，不信任前端身份头。`by-tenant` 的状态校验必须包含 `sys_datasource.inactive=0` 与 `del_flag=0`。system 管理接口的 `tid` 用于数据过滤，不触发切库；业务微服务的 `tid` 由拦截器用于切库。租户切换后前端重新调用 `getLoginInfo()` 拉取菜单并重建动态路由。

## 10. 非功能需求

| 类别 | 要求 |
|---|---|
| 安全 | 数据源密码 AES+Base64，密钥独立配置且禁止硬编码；明文不落库、不进日志、不进缓存；越权校验只信服务端会话，uid 头不可信 |
| 连接测试 | 5s 内返回；单次临时连接并立即关闭，不注册物理池、不影响 `MAX_DATASOURCE_COUNT`；错误堆栈与响应必须脱敏，禁止回显 URL 参数与账号密码 |

| 可观测 | 切库 key、初始化步骤、失败原因、越权告警均记录日志；全局 loading 走 `SmartLoading` |

## 11. 验收标准

| 场景 | 给定 / 当 / 那么 |
|---|---|
| 新建租户 | 给定活跃租户"华东科技"存在；当再次新建同名；那么保存失败并提示名称已存在；逻辑删除后可重建 |
| 编辑数据库名 | 给定租户已初始化；当打开编辑抽屉；那么 `database_name` 只读且接口拒绝修改 |
| 共享库隔离 | 当选择 `isolation_mode=2` 并提交；那么接口拒绝并提示暂未开放 |
| 数据源密码 | 给定已有数据源；当编辑时密码留空保存；那么原密文保持不变，连接仍可用 |
| 测试连接 | 给定填写完整的 JDBC URL/账号/密码；当点击"测试连接"；那么 5s 内返回成功（含耗时与数据库版本）或脱敏失败原因；日志、响应与缓存中均无明文密码，且不新增物理连接池 |
| 编辑态测试连接 | 给定已保存数据源且编辑时密码留空；当点击"测试连接"；那么服务端临时解密已存 `password_cipher` 完成测试，成功后仍不改写原密文 |
| 引用保护 | 给定数据源被未删除租户引用；当执行删除；那么拒绝并列出引用租户 |
| 初始化 | 当执行初始化；那么 `init_status` 依次 0→1→2 或 3，仅成功时写入 `database_name=tenant_{id}` |
| 重新初始化 | 给定 `init_status=2` 的租户；当平台超管二次确认后以 `force=true` 提交；那么状态回到 1，执行期间保留原 `database_name`，失败不清空 |
| 启动即时返回 | 当点击"执行初始化"；那么接口立即返回 `taskId`，不等待脚本执行完成，弹窗进入进度视图 |
| 实时进度 | 给定初始化任务进行中；当 SSE 推送步骤事件；那么进度条、当前步骤名与日志实时更新，最终以 `success`/`fail` 事件结束并同步列表状态 |
| 断线续接 | 给定 SSE 连接中断；当 EventSource 自动重连并携带 `Last-Event-ID`；那么服务端先补发任务快照，再从断点继续推送，不重复执行脚本 |
| 库名可用 | 给定目标库 `tenant_{id}` 不存在；当执行初始化；那么先完成 `DB_EXISTS_CHECK`，再执行 `CREATE_DATABASE`，随后按 `application_code` 顺序执行脚本，全部成功后写入 `database_name` |
| 库名已存在 | 给定目标库已存在且非当前任务创建；当执行初始化；那么在 `DB_EXISTS_CHECK` 步骤失败，`init_status=3`，不执行 `CREATE_DATABASE`、不执行任何应用脚本、不回写 `database_name` |
| 脚本失败重试 | 给定 OA 脚本成功、HR 脚本失败且快照 `databaseCreated=true`；当点击重试；那么跳过预检结论复用与 `CREATE_DATABASE`，从 HR 脚本继续，OA 脚本不重复执行 |
| 重新初始化 | 给定 `init_status=2` 且库归属当前租户；当超管确认后以 `force=true` 提交；那么跳过 `CREATE_DATABASE`，幂等重放应用脚本，执行期间保留原 `database_name` |
| 并发互斥 | 给定租户已有运行中初始化任务；当再次点击初始化；那么拒绝新任务并提示"该租户正在初始化" |
| 用户授权 | 当给用户添加租户；那么其登录后 `tenantIds` 包含该租户，切换器可选；移除后不可选 |
| 菜单白名单 | 当租户白名单未勾选某菜单；那么即使角色已授权，该用户菜单中也不出现 |
| 应用归属过滤 | 当租户 `application_code` 不包含某应用；那么该应用菜单不进入白名单树，也不出现在该租户用户菜单中 |
| 菜单归属 | 给定租户管理/数据源配置菜单及其按钮；当检查 `sys_menu.application_code`；那么全部为 `system`，权限串以 `system:tenant:*` / `system:datasource:*` 开头；白名单引用不改变归属 |
| 门户候选租户 | 给定用户拥有多个租户；当进入门户；那么切换器只展示已初始化、未停用、未过期且已授权的租户 |
| 门户卡片联动 | 当在门户从租户 A 切换到租户 B；那么应用卡片、KPI、待决策与事件流按 B 的 `tid` 重新拉取，旧租户数据置灰且不可操作 |
| 门户平台卡片 | 给定平台管理员切换到任一租户；那么租户管理、数据源配置、Agent 治理等平台级卡片仍按平台权限显示，不被租户应用过滤 |
| Agent 上下文隔离 | 当门户切换租户；那么 Agent/AI 会话上下文被重置或明确标记，不携带上一租户的数据与工具调用结果 |
| 过期租户 | 当租户 `expire_time` 已过期；那么切换器不展示该租户，选择或携带其 `tid` 时返回 `system.tenant.expired` |
| 切库 | 当用户选中 `tid=12`；那么请求头携带 `tid=12`，拦截器校验授权后路由到 `tenant_12` |
| 越权 | 当 `tid` 不在授权集合；那么返回 `system.tenant.forbidden`，不发生切库 |
| 单租户登录 | 给定用户仅授权 1 个租户；当登录成功；那么自动选中该租户，后续请求携带其 `tid`，无需用户选择 |
| 多租户登录 | 给定用户授权多个租户；当登录成功；那么默认选中第一个可用租户并在顶栏显式展示，切换器可切换到其他授权租户 |
| 无租户登录 | 给定用户无任何可用租户；当进入门户；那么租户级卡片显示空状态，不发起带 `tid` 的业务请求 |
| 多标签页租户隔离 | 给定同一用户在两个标签页分别选择不同租户；那么两个标签页的请求各自携带自己的 `tid`，互不影响 |

## 12. 风险与待确认事项

| 编号 | 问题 | 影响 | 建议 / 待确认 |
|---|---|---|---|
| R01 | `sys_tenant_user` / `sys_tenant_menu` 唯一键包含已删除行 | 软删后重新授权冲突 | 本期采用物理删除；下个脚本改条件唯一键（确认是否接受） |
| R02 | `sys_datasource.datasource_name` 无活跃唯一约束 | 下拉重名、运维误选 | 建议 5.2 增加生成列 + 条件唯一索引 |
| R03 | 过期租户的严格程度待确认 | 过期租户目前按 BR-09"不可切换 + `system.tenant.expired`"处理；是否需要保留只读访问 | 需产品确认文案；若要求只读，需额外定义只读路由与数据范围 |
| R04 | `application_code` 取值域未维护 | JSON 集合可能引用不存在应用 | 建议新增应用字典或配置项校验，需确认应用清单 |
| R05 | 初始化脚本目录与 app 映射未落地 | 初始化器无法定位脚本 | 需确认目录约定（如 `sql/init/{application_code}/`）与幂等要求 |
| R06 | 缓存失效时机 | 授权变更后 Redis 会话中的 `tenantIds` 与 resolver 缓存仍保留旧租户，300s 内可继续访问 | 关系/租户/数据源变更时主动清理会话 `tenantIds`、`tenant:user:{userId}`、`tenant:ds:{tenantId}`；必要时强制会话重新签发 |
| R07 | 文档与配置不一致 | README/starter README 仍描述旧行为 | 同步修正文档与 `application.yml` 开关 |
| R08 | 共享库行隔离预留 | 未来开放时数据模型不足 | 保持接口拒绝，不提前暴露配置 |
| R09 | 测试连接异常堆栈可能携带 JDBC URL 参数或账号 | 敏感信息泄露到前端/日志 | 统一捕获异常并只返回脱敏摘要；日志使用固定文案 + 异常类型，不打印完整 URL 与密码 |
| R10 | 驱动与网络策略差异 | 测试成功但运行时失败，或测试被防火墙拦截 | 明确允许的 JDBC 驱动白名单；测试与运行时使用同一连接参数构造逻辑；超时统一 5s |
| R11 | 混淆 `sys_tenant.application_code` 与 `sys_menu.application_code` | 平台管理菜单被误配到 OA/HR/CRM，导致租户白名单按应用过滤时错误暴露或隐藏菜单 | 菜单初始化脚本显式写 `application_code='system'`；评审时核对菜单归属与权限串前缀 |
| R12 | 切换租户后旧数据残留 | 用户误点旧租户待办/卡片，造成跨租户误操作 | 切换期间置灰并禁用交互；重新拉取门户概览；重置 Agent/AI 上下文；前端不再复用旧响应 |
| R13 | 应用注册表缺少 `scope` / `applicationCode` | 平台级卡片被租户应用过滤，或租户级卡片无法按开通应用过滤 | 门户应用注册表显式声明 `scope=platform|tenant` 与 `applicationCode`；后端聚合接口统一返回该结构 |
| R14 | SSE 被代理缓冲或超时断开 | 进度不实时或连接中断 | 配置 `text/event-stream` 直通、关闭缓冲；15s 心跳；前端按 `Last-Event-ID` 续接并先补发快照 |
| R15 | 任务状态未持久化或重复启动 | 刷新后看不到进度，或同一租户重复执行脚本 | 任务状态写 Redis（TTL 24h）+ `sys_tenant_init_task` 记录表；启动前校验运行中任务互斥 |
| R16 | 同名库被误判为可创建 | 覆盖或清空已有业务库，造成数据丢失 | 预检必须只读判断，不执行 `DROP`/`TRUNCATE`；未知同名库直接失败；仅快照 `databaseCreated=true` 或 `force=true` 且归属当前租户时可跳过建库 |
