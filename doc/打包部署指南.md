# mcdull 打包与部署指南

> 适用版本：revision 1.0.0（Spring Boot 3.5.16 / Java 17 / Maven 3.8+）
> 本文档覆盖：环境准备、一键构建、按模块打包、运行与部署、版本变更流程、常见问题。

## 一、环境准备

| 组件 | 要求 | 说明 |
|---|---|---|
| JDK | 17+ | `mvn -v` 确认 Maven 使用的是 JDK 17（见下方高频坑） |
| Maven | 3.8+ | 需支持 CI-Friendly `${revision}` 版本 |
| 数据库 | MySQL 8.x | 业务服务启动必需（tools 除外） |
| 注册/配置中心 | Nacos 2.x | gateway / mdc-provider 需要 |
| Redis | 6.x+ | 缓存与 Sa-Token 会话 |

国内环境建议在 `~/.m2/settings.xml` 配置阿里云镜像加速依赖下载。


## 二、工程结构速览

```
mcdull
├── mcdull-framework        框架层（纯依赖，不可独立运行）
│   ├── mcdull-framework-dependencies   BOM：全仓版本归口
│   ├── mcdull-framework-base           通用基座（Result/VO/领域引擎）
│   └── mcdull-framework-starters       13 个能力 starter
├── mcdull-business        业务层
│   ├── system  →  system-bootstrap  可执行服务 :8099
│   ├── blaze   →  blaze-bootstrap   可执行服务 :8090
│   └── focus   →  focus-bootstrap   可执行服务 :6060
└── mcdull-support          支撑层（独立进程）
    ├── mcdull-gateway      网关       :9090
    ├── mcdull-mdc          元数据服务（mdc-provider）
    ├── mcdull-monitor      Boot Admin :9000
    └── mcdull-tools        运维工具台 :7080（无 MySQL 依赖）
```

## 三、一键全量构建（最常用）

```bash
# 克隆后首次构建（跳过测试）
mvn clean install -DskipTests

# 指定版本号构建（CI/发布用）
mvn clean install -DskipTests -Drevision=1.0.0
```

- `install` 会把所有模块 jar 装入本地仓库，同时为带 `spring-boot-maven-plugin` 的模块生成**可执行 fat-jar**。
- 构建产物位于各 `*-bootstrap` / `mcdull-gateway` / `mcdull-mdc-provider` 等模块的 `target/` 目录，形如 `system-bootstrap-1.0.0.jar`。

### 构建顺序说明
Maven reactor 自动按依赖排序：`framework-dependencies(BOM) → framework-base → starters → business-common/facade → impl → bootstrap`，无需手动排序。

## 四、按模块打包（日常开发推荐）

只构建某个服务及其依赖链，速度快：

```bash
# 系统服务（-am 表示连同依赖模块一起构建）
mvn clean package -DskipTests -pl mcdull-business/mcdull-business-system/system-bootstrap -am

# 核心业务
mvn clean package -DskipTests -pl mcdull-business/mcdull-business-blaze/blaze-bootstrap -am

# 网关
mvn clean package -DskipTests -pl mcdull-support/mcdull-gateway -am

# 元数据服务
mvn clean package -DskipTests -pl mcdull-support/mcdull-mdc/mcdull-mdc-provider -am

# 监控中心 / 运维工具台（无业务依赖，可不加 -am）
mvn clean package -DskipTests -pl mcdull-support/mcdull-monitor
mvn clean package -DskipTests -pl mcdull-support/mcdull-tools
```

> 注意：`-pl` 必须使用**子模块路径**（如 `.../system-bootstrap`），而不是 artifactId。

## 五、运行与部署

### 1. 本地运行（开发）

```bash
# 方式一：Maven 直接跑（需模块内有 spring-boot:run 配置或主类）
mvn spring-boot:run -pl mcdull-business/mcdull-business-system/system-bootstrap

# 方式二：IDE 直接运行 *Application 主类（推荐，支持 profile）
#   VM options: -Dspring.profiles.active=dev
```

### 2. 服务器部署

```bash
# jar 自包含全部依赖，服务器仅需 JDK 17
java -jar system-bootstrap-1.0.0.jar --spring.profiles.active=prod

# 推荐：外置配置 + 后台运行
nohup java -Xms512m -Xmx1g \
  -jar system-bootstrap-1.0.0.jar \
  --spring.profiles.active=prod \
  --spring.config.additional-location=./config/ \
  > logs/system.out 2>&1 &
```

| 服务 | 默认端口 | 启动前置条件 |
|---|---|---|
| mcdull-monitor | 9000 | 无（最先启动） |
| mcdull-mdc-provider | 见 bootstrap.yml | MySQL + Nacos |
| mcdull-gateway | 9090 | Nacos |
| system-bootstrap | 8099 | MySQL + Nacos + Redis |
| blaze-bootstrap | 8090 | MySQL + Redis（依赖 system 服务在线） |
| focus-bootstrap | 6060 | MySQL |
| mcdull-tools | 7080 | 无（已排除 MySQL） |

建议启动顺序：**monitor → mdc-provider → system → gateway → 其他业务服务**（gateway/blaze 的 Feign 调用依赖 mdc 与 system 在线）。

### 3. Docker 部署（可选）

```dockerfile
FROM eclipse-temurin:17-jre
WORKDIR /app
COPY system-bootstrap-1.0.0.jar app.jar
EXPOSE 8099
ENTRYPOINT ["java","-jar","app.jar","--spring.profiles.active=prod"]
```

## 六、版本变更流程（重要）

全仓版本由根 POM 的 `${revision}` 统一控制（BOM 已纳入同一体系，无硬编码版本）：

```bash
# 一条命令升级全仓版本（含 BOM）
mvn clean install -DskipTests -Drevision=1.0.1

# 或修改根 pom.xml 的 <revision>1.0.0</revision> 后正常构建
```

发布到 Sonatype（snapshot/release）：

```bash
mvn clean deploy -Drevision=1.0.1 -DskipTests   # 需 ossrh 账号与 GPG 签名配置
```

## 七、常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `Non-parseable POM ... Duplicated tag` | 手工改 POM 引入重复标签 | 检查 `<properties>` 等段是否重复 |
| `version is missing` 某依赖报错 | BOM 未正确 import 或 BOM 构建失败 | 先确认 `mcdull-framework-dependencies` 构建通过 |
| 打出的 jar 无法 `java -jar` 启动 | 模块缺少 `spring-boot-maven-plugin` 的 `repackage` 执行 | 确认模块 pom 声明了该插件（bootstrap/gateway/mdc/tools 已有） |
| 启动报 `NoSuchBeanDefinition: SwitchableDataSource` | 使用了 `@EnableWebCore` 但未启用数据源 | 加 `@EnableDynamicDataSource` 并配置 MySQL |
| flatten 报错或版本号仍是 `${revision}` | Maven < 3.8 或未传 revision | 升级 Maven；单模块构建时加 `-Drevision=...` |
| 依赖下载慢/失败 | 网络问题 | settings.xml 配置阿里云镜像 |

## 八、CI 建议

1. 流水线统一使用 `-Drevision=${GIT_TAG}` 注入版本，做到"tag 即版本"；
2. 在编译阶段追加 `mvn dependency:analyze`，防止业务模块重新出现隐式传递依赖（P0-4）；
3. 可接入 `mcdull-framework-enforcer`（ArchUnit）做架构守护测试，目前该模块规则已就绪但尚无测试调用。
