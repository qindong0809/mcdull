## 1. 总体设计

### 1.1 模块定位

本模块属于**平台侧系统管理 / 租户治理中心**，代码落在 `mcdull-business-system`，数据落在 master 库，不属于 OA/HR/CRM 等业务应用，也不属于 framework 框架层。

职责边界：

| 层 | 职责 |
|---|---|
| system-facade | 定义 `TenantDataSourceApi` 内部 RPC 契约 |
| system-impl | 租户/数据源 CRUD、初始化任务、登录租户集合、门户聚合、内部接口实现 |
| framework-spi | 定义 `TenantDataSource`、`TenantDataSourceResolver` 抽象 |
| framework starter-mysql | 通过 `DynamicDatasourceInterceptor` 按 `tid` 切库 |
| 业务微服务 | 消费 `tid`，在租户库内处理业务数据 |
| mcdull-vue3 | 系统管理页面、租户切换器、门户联动、SSE 进度展示 |

### 1.2 关键链路

```text
登录
  → 查 sys_tenant_user join sys_tenant 生成 tenantIds 写 Redis 会话
  → getLoginInfo 返回 tenantList / menuList
  → 前端默认选中租户（单租户自动，多租户默认第一个）
  → 请求头 tid=currentTenantId

业务请求
  → DynamicDatasourceInterceptor 校验 tid ∈ session.tenantIds
  → resolver 调用 TenantDataSourceApi.by-tenant
  → 读 sys_tenant + sys_datasource，解密密码
  → 以 database_name=tenant_{id} 作为 lookupKey 切库

初始化
  → POST /system/tenant/{id}/init 返回 taskId
  → 异步任务：预检库名 → 不存在则建库 → 按 application_code 执行脚本 → 回写 database_name
  → SSE 推送 DB_EXISTS_CHECK / CREATE_DATABASE / APP_SCRIPT / WRITE_BACK 进度

门户
  → 当前租户决定租户级应用卡片 / KPI / 待办 / 事件流
  → 平台级卡片只按平台权限显示
```

### 1.3 设计原则

- 沿用项目现有 `Result` / `InnerResult` / `BasicCurdServiceImpl` / `SaCheckEL` / i18n 体系。
- 新增类命名沿用 `XxxController` / `IXxxService` / `XxxServiceImpl` / `XxxMapper` / `XxxEntity` / `XxxAddDTO` / `XxxVO`。
- 前端沿用 `smart-query-form`、`smart-table-*`、`a-drawer + smart-form sf-form-drawer`、`v-privilege`。
- 选择类控件选中态使用 `var(--sf-primary)`，不加大任何字号，不自造按钮皮肤。
- 数据源密码独立 AES 密钥，明文不落库、不进日志、不进缓存。
- 初始化任务状态必须可持久化，支持断线续接和幂等重试。

### 3.2 新增 sys_tenant_init_task

建议新增 `sql/5.2_tenant_init_task.sql`：

```sql
CREATE TABLE IF NOT EXISTS `sys_tenant_init_task` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键',
  `task_no` varchar(64) NOT NULL COMMENT '任务号，SSE 订阅标识',
  `tenant_id` int NOT NULL COMMENT '租户ID',
  `datasource_id` int NOT NULL COMMENT '数据源ID',
  `database_name` varchar(64) NOT NULL COMMENT '目标库名 tenant_{id}',
  `status` tinyint NOT NULL DEFAULT 0 COMMENT '0运行中 1成功 2失败',
  `current_step_code` varchar(32) DEFAULT NULL COMMENT 'DB_EXISTS_CHECK/CREATE_DATABASE/APP_SCRIPT/WRITE_BACK/DONE',
  `progress` int NOT NULL DEFAULT 0 COMMENT '0-100',
  `database_created` tinyint NOT NULL DEFAULT 0 COMMENT '本次任务是否由系统创建数据库',
  `force_flag` tinyint NOT NULL DEFAULT 0 COMMENT '是否重新初始化',
  `application_codes` text COMMENT 'application_code JSON 数组字符串',
  `script_statuses` text COMMENT '各应用脚本执行状态 JSON',
  `error_code` varchar(64) DEFAULT NULL COMMENT '错误码',
  `error_message` varchar(512) DEFAULT NULL COMMENT '脱敏错误摘要',
  `started_time` datetime DEFAULT NULL,
  `finished_time` datetime DEFAULT NULL,
  `created_by` bigint DEFAULT NULL,
  `created_time` datetime DEFAULT NULL,
  `updated_by` bigint DEFAULT NULL,
  `updated_time` datetime DEFAULT NULL,
  `inactive` tinyint NOT NULL DEFAULT 0,
  `del_flag` tinyint NOT NULL DEFAULT 0,
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_init_task_no` (`task_no`),
  KEY `idx_init_task_tenant` (`tenant_id`, `status`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='租户初始化任务记录';
```

说明：

- `database_created` 是重试是否跳过建库的关键依据。
- `script_statuses` 示例：`{"OA":"success","HR":"failed"}`。
- 任务状态同时写 Redis（`tenant:init:{taskNo}`，TTL 24h），DB 用于历史与重启恢复。

### 4.7 Manager 设计

#### DatasourceCryptoManager

- 参照 `PasswordManagerImpl`，新增 `@ConfigurationProperties(prefix = "mcdull.security.datasource")`。
- `encrypt(String plain)`：AES + Base64。
- `decrypt(String cipher)`：Base64 + AES。
- `@PostConstruct` 校验 key 为 32 字节；禁止使用内置默认密钥上生产。

配置：

```yaml
mcdull.security.datasource.aes-key: ${MCDULL_DATASOURCE_AES_KEY:}
mcdull.tenant.init-script-dir: ${MCDULL_TENANT_INIT_SCRIPT_DIR:sql/init}
mcdull.tenant.task-ttl-seconds: 86400
```

#### DatasourceConnectionTester

- 使用 `DriverManager.getConnection(jdbcUrl, username, plainPassword)`。
- 5s 超时：`DriverManager.setLoginTimeout(5)`。
- 不注册物理连接池，不写库，不缓存明文。
- 返回 `success`、`message`、`latencyMs`、`databaseProduct`、`databaseVersion`。
- 异常统一脱敏，禁止打印完整 URL 与密码。

#### TenantInitExecutor

执行顺序固定：

```text
1. DB_EXISTS_CHECK：只读检查目标库是否存在
2. CREATE_DATABASE：仅当不存在且非重试/force 时执行
3. APP_SCRIPT：按 application_code 顺序执行 sql/init/{code} 下脚本
4. WRITE_BACK：全部成功后写 database_name + init_status=2
```

关键规则：

- 未知同名库：立即 `fail`，`failedStepCode=DB_EXISTS_CHECK`，不建库、不执行脚本、不回写。
- 建库失败：`failedStepCode=CREATE_DATABASE`。
- 任一脚本失败：`failedStepCode=APP_SCRIPT`，保留 `databaseCreated=true` 与 `scriptStatuses`。
- 重试：若 `databaseCreated=true`，跳过建库，从失败脚本继续；脚本使用幂等语句。
- `force=true`：库归属当前租户时跳过建库，幂等重放全部脚本。
- 严禁 `DROP DATABASE` / `TRUNCATE` 未知同名库。

#### TenantInitProgressPublisher

仿 `LogTailPublisher`：

- `CopyOnWriteArrayList<Subscriber>` 管理订阅者。
- `subscribe(taskNo, lastEventId)`：先 `snapshot`，再注册，按事件序号补发。
- `publish(TenantInitProgressVO)`：发送 `SseEmitter.event().name(...).data(...)`。
- 每 15s `comment("hb")` 心跳。
- `onCompletion/onTimeout/onError` 清理订阅者。
- 事件名：`snapshot`、`step`、`log`、`progress`、`success`、`fail`、`heartbeat`、`done`。

#### TenantCacheEvictManager

统一清理：

```text
tenant:ds:{tenantId}
tenant:user:{userId}
tenant:init:{taskNo}
用户会话中的 tenantIds（通过 Sa-Token session key current:user:{id}）
```

触发点：租户用户变更、租户启停/删除、租户初始化成功、数据源变更、数据源启停/删除。

| Key | 内容 | TTL | 失效时机 |
|---|---|---|---|
| `tenant:ds:{tenantId}` | `RemoteTenantDataSourceVO`（密码密文） | 300s | 租户/数据源变更、初始化成功、启停 |

4. 平台管理员切换租户 → 平台管理卡片仍在，租户业务卡片按当前租户变化。

## 12. 风险与注意事项

| 编号 | 风险 | 规避措施 |
|---|---|---|
| C01 | `.javav` 后缀文件不参与编译 | 若依赖 `BaseInfoInterceptor` / `OperationLogsAspect`，先重命名为 `.java` 并确认启用 |
| C02 | Sa-Token 会话中 `tenantIds` 与 resolver 缓存不一致 | 授权变更统一走 `TenantCacheEvictManager`，必要时强制重签会话 |
| C03 | 原生 EventSource 无法携带 Authorization/tid | 前端使用 fetch-stream 封装，服务端兼容 query `tid`；token 不放 URL |
| C04 | SSE 被网关缓冲 | `text/event-stream` 直通、关闭缓冲、15s 心跳 |
| C05 | 初始化重试重复建库/覆盖已有库 | `databaseCreated` 快照 + 未知同名库直接失败 + 禁止 DROP/TRUNCATE |
| C06 | 数据源明文泄露 | 独立 AES 密钥、脱敏日志、缓存只存密文、测试连接用完即弃 |
| C07 | 关系表唯一键含已删除行 | 租户用户/菜单关系移除使用物理删除 |
| C08 | 前端当前租户误写 localStorage | 使用 sessionStorage，保证多标签页独立 |
| C09 | 菜单归属误配 | 菜单初始化脚本显式 `application_code='system'` |
| C10 | 动态数据源数量超限 | resolver 与初始化均校验 `MAX_DATASOURCE_COUNT`，超限返回 `system.datasource.limit` |
